# Morpheus 设想 vs Lyra 现状 —— 差距分析

## 一、共同基因（先说重叠）
两者都押注**情感建构 + 界面即情绪身体**：Lyra 已用 PAD 三维坐标系（`EmotionAgent`）+ 山水 Canvas（`ShanShuiCanvas`）+ 每周信件 + 反馈修正闭环，把《How Emotions Are Made》的建构论落成了工程。这个骨架和 Morpheus 的哲学是**同一条脊柱**。

## 二、四个数量级差距

### 1. 感知：**语言 → 生理**（差 1 个物理层）
- **Lyra**：靠用户话语 + 交互事件 → LLM 推断 PAD。
- **Morpheus**：心率/皮电/肌电/脑电实时驱动，"无感共振"。
- **差距**：缺**可穿戴 SDK 接入层**（Apple Watch HealthKit / Oura Ring / Muse），缺**生理信号 → PAD 融合器**。需求文档里写了"和智能戒指连接"，代码里零踪迹。

### 2. 输出：**选曲 → 生成**（差整个引擎）
- **Lyra**：`LibraryAgent.prefilter` + `CompanionAgent.choose` 从**本地曲库**里挑一首。天花板 = 用户曲库上限。
- **Morpheus**：**实时 AI 音乐生成**，为此刻创造独一份的声音结构，还能做"30 秒不和谐 → 舒缓"的情绪引导曲线。
- **差距**：这是**范式差**，不是功能差。要接 Suno/Udio/MusicGen 类生成模型，还要做**情绪引导的时序编排层**（当前 Lyra 只做单点匹配，不做过渡曲线）。

### 3. 交互：**被动听 → 主动共创**（差一整个模态）
- **Lyra**：文本对话 → 选歌 → 听。
- **Morpheus**：哼唱输入 → 展开配器 / 悬停在属七和弦让用户选"预期解决"还是"意外之美" / 3D 沙盘拖拽和声色块。
- **差距**：缺**音频输入通道**（麦克风哼唱识别）、缺**乐理可视化操作面**、缺**分支叙事的和声引擎**。这部分 Lyra 完全没起步。

### 4. 社群：**孤岛 → 全球共振场**（差整个后端）
- **Lyra**：本地 SQLite，纯单机 agent，隐私是卖点。
- **Morpheus**：全球情绪地图 + 匿名合奏 + 记忆胶囊的跨时空共情。
- **差距**：需要**云端脱敏聚合服务**——但这**直接冲突** Lyra "数据留在你机器上"的立场（`feature-gaps.md` P0 #5 Ollama 就是这个立场的产物）。**不是能不能做，是要不要做**。

## 三、真正的战略选择

| 维度 | Lyra 当前 | Morpheus 愿景 | 建议 |
|---|---|---|---|
| **感知** | 语义 | 生理 | ✅ 加戒指/表 SDK，与现有 PAD 融合，风险低 |
| **输出** | 选曲 | 生成 | ⚠️ 版权/成本/延迟三座山，先做**过渡曲线编排**（连播两首形成引导弧） |
| **交互** | 对话 | 共创 | 🔶 先做"哼唱一句 → 找回一段记忆歌"，比生成配器落地 10 倍 |
| **社群** | 单机 | 全球场 | ❌ 与产品立场冲突，暂缓；改做**跨设备的个人时间线胶囊** |

## 四、一句话结论

**Lyra 是 Morpheus 的"语义半身"，缺的是"生理半身"和"生成半身"。**

短期最高 ROI 的补齐顺序：
1. **智能戒指信号接入**（把需求文档里的承诺兑现，和现有 PAD 融合）
2. **情绪引导的多曲编排**（不做生成，做"连播弧线"，一首接一首把用户从 A 状态导到 B 状态）
3. **记忆胶囊 v0**（不做跨用户共情，做**给未来的自己**——把此刻 PAD + 环境 + 一首歌封成一个可以在明年某天被 Lyra 主动打开的"时间信"）

**Morpheus 是终局，Lyra 是起点。** 距离不是"要不要做"，而是"按什么顺序，付得起哪一段代价"。
