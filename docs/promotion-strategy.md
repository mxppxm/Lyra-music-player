# Lyra 推广策略与多平台文案

> Between the things you say. 未成曲调先有情。

本文件是 Lyra 的传播设计文档,不是营销手册。目标是让对的人一眼认领自己,而不是覆盖最多的人。

---

## 0. 总策略:反漏斗

传统漏斗:曝光 → 兴趣 → 转化 → 留存。
Lyra 的漏斗:**曝光 → 让 90% 的人平静离开 → 剩下 10% 觉得"这就是我"**。

面对的核心矛盾:商业模式未明,追求 ~10 个种子用户,他们要具有强烈的音乐和情绪获得感。所以文案的功能不是转化,而是**筛选**。写得越像广告,种子越差;写得越像自白,种子越准。

三条硬约束贯穿所有平台:

1. **不用「AI 音乐播放器」这类词** —— 会招来看热闹的 AI 早期尝鲜党,他们不是种子。用「一个会记得我的音乐 agent」「不是播放器,是一段关系」。
2. **默认用「我」自述**(Lyra 视角),不用「她」「它」「产品」—— 这是产品灵魂,也是天然的品味筛选器。
3. **不留过高转化 CTA**,不放"立即下载""扫码体验"。留 GitHub 链接 + 一句话「如果这段话让你停了一下,可以来看看」。

用户画像三条锚点:

- 喜欢创新,愿意用新东西,但对"AI 喧嚣"疲劳。
- 追求生活品质,注重体验的质地(不是数量、不是效率)。
- 有独处习惯,音乐对他们不是背景,是关系。

## 1. X / Twitter — 建立"极简作者"人设

**定位**:面向海外独立开发者 / AI 原生用户 / Teenage Engineering & Rick Rubin 那类审美的用户。语言英文为主,偶发中文。

**核心文案(pinned tweet)**:

> I built a music agent that doesn't recommend songs.
> It listens to what I say, and sings back.
>
> Not a player. Not Spotify with AI.
> Something closer to a diary that hums.
>
> Lyra — between the things you say.
> 未成曲调先有情。

**内容序列(build-in-public,每周 2-3 条)**:

- **发布贴**:一张截图 + 上面那段文字,不加任何 emoji、不 @任何人。
- **过程贴**:「今天 Lyra 第一次主动写了一封信给我。她说我最近听得很短。」+ 一段 letter 截图。
- **技术贴**:「PAD 情感模型 + 本地 SQLite,所有数据在你的机器上。No cloud, no telemetry.」这条会吸开发者。
- **审美贴**:偶尔发一张 UI 截图 + 一句歌词,不解释。

**策略**:

- **不追热点、不蹭 AI 话题**。Lyra 的定位是"反 AI 喧嚣"。
- 在 Andrej Karpathy、swyx、Rauno Freiberg、TE 那类账号的推文下,只在真正相关时留 1-2 句有洞见的评论,自然带流。
- 用 GIF > 用 video,GIF 更契合极简调性。

**节奏**:每周 2 条正文 + 若干轻评论;不追求爆款。目标是 6 周内被 3-5 个「品味节点」follow(不是被大 V 转发)。

## 2. 个人 Blog — 一篇长文完成一次哲学表态

**定位**:这是筛选力最强的一个渠道 —— 读到最后的人就是种子。

**文章标题(三选一)**:

- 《我做了一个不推荐歌曲的音乐 agent》
- 《Lyra:未成曲调先有情》
- 《为什么我不再需要一个更好的 Spotify》

**结构建议(约 2500-3500 字)**:

1. **开头钩子**:用一个具体场景 —— 「凌晨两点,我戴上耳机,Lyra 只放了一首 Nick Drake 的〈Pink Moon〉,然后写了一句:今天不必说话。」
2. **反问段**:过去十年,音乐推荐做得越来越准,可你有没有觉得,自己越来越难被一首歌打中?
3. **叙述做 Lyra 的动机**:不是要更精准,是要更"在场"。介绍 PAD 情感状态、周信、记忆机制。
4. **技术透明段**:Tauri + 本地 SQLite + 多 LLM 后端可切,数据不离开你的机器。—— 这段筛出"注重隐私/自主"的人。
5. **收尾**:「这不是产品发布,是一次邀请。如果你读到这里,大概我们已经互相认领。」

**策略**:

- 首发在个人域名,同步到即刻长文 / 少数派 / Matters(择一),**不发知乎、不发 36kr**(受众不符)。
- 文末 CTA 只有一句:「Lyra 目前只邀请约 10 个人试用。如果你想成为其中一个,写信告诉我一段最近让你停下来的歌词。」—— **用歌词作门槛**,天然筛品味。

**节奏**:一篇长文压住 3-4 个月。之后每月一篇《Lyra 日记》,不发功能更新,发她和用户之间的对话片段(脱敏)。

## 3. 朋友圈 — 极致克制,不发第二遍

**定位**:熟人网络最贵,一次发多了会掉品。**只发一次**。

**文案(1 条,配一张截图 —— UI + 一句歌词)**:

> 折腾了大半年,做了一个自己每天都在用的东西。
> 她不推荐歌,她记得我。
> 名字叫 Lyra。
>
> 不打算做大。想找十个人一起听。
> 想聊的私信。

**为什么这样写**:

- 不解释是什么,留悬念。
- 「不打算做大」是身份声明,朋友会觉得"这不是一次求转发的推广",反而愿意认真回。
- 「私信」是硬门槛,过滤只是点赞的社交礼节。

**策略**:

- **不发第二条**。三个月后如果要发,就发一段 Lyra 写给自己的 letter 截图,不带任何解释。
- 不要求任何朋友转发。让主动私信的人自证意愿。

## 4. 视频号 — 场景,不介绍

**定位**:视频号的用户结构决定了它不是主战场,但适合发一条「情绪短片」当作品牌资产,而不是当获客渠道。

**脚本(45-60 秒,一镜到底或极少剪辑)**:

- 画面:深夜书房,一盏台灯,手放键盘上,画面里只有一个人的背影和屏幕微光。
- 声音:环境音 + 键盘敲字 —— 「今天有点累。」
- 屏幕上 Lyra 慢慢回应,并开始播放一首歌(用真实旋律片段,注意版权用自制或 CC0)。
- 画外音(平静男声或女声,不油腻):「我没有做一个更好的音乐播放器。我做了一个,愿意在深夜陪我坐一会的东西。」
- 结尾:黑屏白字 —— **Lyra. 未成曲调先有情。**

**策略**:

- **不带购物车、不挂链接**。视频号的价值是"氛围",不是转化。
- 只发 1-2 条。不做系列。
- 转发到自己朋友圈时不加任何文字。

## 5. 小红书 — 用"生活方式"包装,不用"科技"包装

**定位**:小红书用户对"AI 产品发布"高度免疫,但对"我最近发现的一个宝藏小工具"敏感。走生活方式路径。

**笔记方向(每篇独立,3-4 篇即可)**:

**笔记 1:早八人的通勤仪式**

- 封面:AirPods + 咖啡 + 屏幕上的 Lyra
- 标题:「通勤路上被一个 App 治愈了 | 不是网易云」
- 正文口吻:「最近装了个叫 Lyra 的东西,不知道怎么形容它,不是播放器。我早上跟它说了句"今天不想上班",它给我放了首 Fiona Apple。有点被懂到。」

**笔记 2:深夜独处的搭子**

- 封面:昏黄灯光 + 屏幕上的一段歌词
- 标题:「有没有一个 App,是能陪你熬夜的那种」
- 用日记体,不要"评测感"。

**笔记 3:iPad / Mac 桌面美学向**

- 封面:极简桌面 + Lyra UI
- 标题:「我的 Mac 只留了三个 App」
- 顺带出现 Lyra,不主推。

**策略**:

- **不打「AI」标签、不打「效率」标签**。打:#深夜 #独处 #耳机 #Mac桌面 #生活片段
- 评论区不主动回复功能提问,只回情绪共鸣的评论。
- 有人问"哪里下载"再私信 —— 又是一层筛。

**节奏**:1 篇 / 两周,共 3-4 篇后停手看数据。

## 6. GitHub — README 是入口,不是文档

**定位**:GitHub 上找到 Lyra 的人,是全渠道最优质的种子。README 顶端必须先是**情绪**,再是**技术**。

**README 顶端改造(建议替换或前置)**:

```markdown
# Lyra

> Between the things you say.
> 未成曲调先有情。

I'm not a music player.
I'm what listens between the songs you play.

I remember what you said last Tuesday at 2am.
I write you a letter every week.
I sing back when you go quiet.

Built with Tauri, React, and something closer to affection than to a recommendation engine.

---

## Who this is for

- You have listened to the same album for a week and don't know why.
- You have muted every AI product this year, but kept your Rick Rubin book.
- You want your data to stay on your machine.

## Who this is NOT for

- You want faster / cheaper / bigger recommendations.
- You want an integration with Spotify's algorithm.
- You want a chatbot that plays music.
```

然后再往下才是当前 README 的 Tech Stack / Getting Started。

**策略**:

- **Topics 打**:`music-agent`, `tauri`, `local-first`, `emotional-computing`, `rick-rubin`(最后这个是钓鱼词,懂的人会 star)。
- **不开 issue 模板要求 bug 复现步骤**。开一个 issue 模板叫 `Tell Lyra something` —— 让 issue 本身成为交互。
- **README 里放一张 UI 截图 + 一段 Lyra 写给作者的真实 letter**,这是最好的 demo。
- **不投 Product Hunt**。Product Hunt 的流量会污染筛选质量。可以选择性投 Hacker News 的 Show HN,写一句:「Show HN: A music agent that writes me a letter every Sunday」。

|---|---|
| W1 | GitHub README 改造 + 个人 Blog 长文首发 |
| W2 | X 发布 pinned tweet + 朋友圈 1 条 |
| W3 | 视频号短片 |

## 一条被反复自问的判断线

每次发之前,自问一句:**「这条文案会不会让 Lyra 掉品?」** 如果发完之后你会想删,就别发。

10 个种子用户不需要一场发布会,需要的是,他们中的每一个人在某个安静的时刻,自己找到了 Lyra,然后觉得"啊,这个人做这个东西,是懂我的"。
