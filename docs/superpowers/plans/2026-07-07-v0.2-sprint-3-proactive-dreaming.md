# v0.2 Sprint 3 — 让她主动（Auto Dream + Proactive Open + Emotion Prediction）

> **For agentic workers:** Use superpowers:subagent-driven-development to dispatch implementers per task. Reviewer step skipped per user's standing directive from Sprint 2.

**Goal:** Turn Lyra from "she waits for you to talk" into "she thinks about you when you're not there and occasionally opens up first." After Sprint 3:
- **Auto dream** runs on a schedule (default 03:14 daily + idle fallback + configurable), so `memory.md` grows a Dream + Facts even when the user never manually pressed Cmd+Shift+R
- **Proactive engine** produces `ProactiveIntent`s, passes them through 6-hard-闸 politeness gate + sulk mode, and — when a morning intent survives — quietly makes the first song of the day already ready-to-listen when the user opens the app
- **System tray** breathes and (optional 档 2) sends a low-key desktop notification when a proactive intent is pending; **never** auto-plays
- **Emotion prediction channel** — EmotionAgent now outputs an optional `predicted_trajectory` for the next 1–2 hours; auto-advance uses it when present, falls back to previous emotion when absent

**Architecture:** Everything is TS-side except tray + notification (new Tauri plugins). New folders: `src/schedule/` (dream timer), `src/proactive/` (engine + kinds), `src/tray/` (tray + notif bridge). Reuses Sprint 2's `reflectNow`, Sprint 1a's memory context, Sprint 1b-β's Orchestrator.

**Tech Stack:** No new frontend framework. Adds:
- Rust: `tauri-plugin-notification = "2"`, `tauri-plugin-tray` is built in
- TS: `@tauri-apps/plugin-notification`

### Interfaces

```typescript
// dreamScheduler.ts
export type DreamSchedulerConfig = {
  dailyTimeHHMM: string;         // "03:14" default
  idleMinutes: number;           // 30 default; 0 = disable idle trigger
  runReflect: () => Promise<void>;
  clock?: () => Date;            // injectable for tests
  onActivityListen?: (cb: () => void) => () => void; // injectable listener
};

export class DreamScheduler {
  constructor(config: DreamSchedulerConfig);
  start(): void;                 // begin timer + attach activity listener
  stop(): void;                  // cancel timer + detach
  /** True if a run is in progress. Blocks concurrent triggers. */
  isRunning(): boolean;
}

export function parseHHMM(s: string): { h: number; m: number } | null;
```

### Behaviour

- **Daily trigger:** every 60 s, check if `now.HH === config.HH && now.MM === config.MM` AND `lastRunISO !== today`. If both, run reflect (guarded by `isRunning`). Persist `lastRunISO` to memory (in-instance is fine — no cross-restart concern for v0.2 dry run).
- **Idle trigger:** attach a global `activitySince = Date.now()` updated on user input events (window focus/blur, click, keydown). Every 60 s check `(Date.now() - activitySince) >= idleMinutes * 60_000` AND `lastIdleRunAt < now - 6h` AND `not in 22:00-06:00 sleep hours`. If yes, run reflect.
- **Concurrency:** a single `_running: boolean` guards all triggers. If `runReflect` throws, log warn + release lock; do not retry same minute.
- **Manual `reflectNow` from Cmd+Shift+R stays outside the scheduler** — the scheduler doesn't intercept it.

### Behaviour (morning kind is the ONLY real one in v0.2)

**morningRule:**
- Fires if `todayFirstOpen === true` AND `now.getHours()` ∈ [5, 12) AND there's no morning intent already fired today
- Sets `urgency = 0.5`, `hint = "早上第一次打开"`, `kind = "morning"`
- If `dreamSeeds` has a morning-kind seed, use its `hint` and prefer its `songHint` in `targetProfile`

**Politeness gate (6 hard checks in order):**
1. `todayProactiveCount >= 3` → skip "daily_limit"
2. `todayKindCount[kind] >= budget[kind]` → skip "kind_budget"
3. `now - lastKindFireAt[kind] < cooldown[kind]` → skip "cooldown"
4. `isFocusOrSleep()` AND NOT (`kind === "care"` AND `urgency >= 0.85`) → skip "focus_or_sleep"
5. `sulkUntil && now < sulkUntil` → skip "sulk"
6. `isPlayingOtherSource()` → skip "playing_other"

Cooldowns per §4.1:
```typescript
const COOLDOWNS: Record<ProactiveKind, number> = {
  morning: 24 * 3600_000,
  care: 6 * 3600_000,
  anniversary: 30 * 24 * 3600_000,
  share: 12 * 3600_000,
  rhythm: 90 * 60_000,
};
const KIND_BUDGETS: Record<ProactiveKind, number> = {
  morning: 1, care: 1, anniversary: 1, share: 1, rhythm: 2,
};
```

**Sulk store:**
- Tracks last 5 proactive outcomes
- Enter sulk (3 days) if last 3 in a row are `dismissed` or `rejected`
- Downgrade to conservative mode (daily_limit → 1) if last 5 in a row are `ignored`
- Clear sulk (set to null) when user actively types (Orchestrator can fire `.clearSulk()` on `onUserInput`)

**Engine.tick(ctx):**
1. For each rule, call it → if returns Intent, collect
2. Sort by `urgency` descending
3. For each intent, run `politenessGate`:
   - If pass → call `fulfill(intent)`, update politeness state (`todayProactiveCount++`, `todayKindCount++`, `lastKindFireAt = now`), stop
   - If fail → log `console.debug`, try next
4. If no intent survives → no-op

**Fulfill(intent):**
- Ask LibraryAgent to pre-filter based on `intent.targetProfile ?? kind default target`
- Ask CompanionAgent to choose (empty user utterance, proactive kind)
- Call `orchestrator.startProactiveIntent(intent, song, rationale)` — orchestrator sets state to a NEW `"proactive-pending"` variant that HomeView renders as "she has something for you" (no cover yet — will reveal on click)
- Actually for v0.2 β, keep it simpler: put the song as the next `playing` turn's queued song. When the user first interacts (types or clicks), if `proactive-pending` exists, transition to `playing`

Detailed presentation flow is T3's job. T2 stops at wiring `startProactiveIntent(intent, song, rationale)` into `Orchestrator` and emitting a new `OrchestratorState = "proactive-pending"`.

    "horizon_min": integer 5-120,

### EmotionAgent validation

Extend `validateEmotion`:
- If `predicted_trajectory` is present:
  - Must have `horizon_min: number in [5, 120]`
  - Must have `predicted_pad` with `p,a,d in [-1,1]`
  - If either is malformed → drop the whole field (don't throw — it's optional)

### Orchestrator autoAdvance change

In the current `onSongComplete → runTurnWithEmotion(endedEmotion, ...)`:
- Compute `elapsed_min = (now - turn.timestamp) / 60_000`
- If `endedEmotion.predicted_trajectory` exists AND `elapsed_min >= 3` AND `elapsed_min <= predicted_trajectory.horizon_min`:
  - Use a synthesized `CurrentEmotion` with `pad = predicted_pad`, same labels, source unchanged, no predicted_trajectory
- Else use `endedEmotion` verbatim
