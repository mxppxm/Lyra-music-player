# v0.2 Sprint 4 — Perception Agent（感知 agent）

> Direct answer to `需求.md` §问题 7: "记住用户所有的事件，包括点击，输入，听歌的状态，歌曲，界面变化等等...转变成当前用户的情绪状态"

**Goal:** Add an event-driven **PerceptionAgent** that silently observes user activity (window focus, input rate, listen duration, skip patterns, session tempo) and infers a *bias* signal on top of `EmotionAgent`'s per-utterance PAD reading. After Sprint 4:
- Every user-facing event (`window.focus`, `window.blur`, `mouseactive`, `keyactive`, `input_submit`, `listen_progress`, `skip`, `complete`, `proactive_dismissed`) flows through a typed `EventBus`
- A `BehavioralAggregator` computes rolling features every 60s (avg typing latency, session length, skip ratio, silence-completion ratio, active time)
- `PerceptionAgent.tick()` reads the features + last N turns and outputs a `PerceptionBias`: `{ pad_bias: PAD, confidence: number, reason: string }`. First implementation is **rules-only** (deterministic); an LLM version is a v0.3 follow-up
- Orchestrator's `onUserInput` blends `EmotionAgent`'s PAD with `PerceptionBias.pad_bias` using confidence-weighted average
- Settings gets a **Privacy: Perception** toggle (default ON) that the user can disable

**Architecture:** All TS-side. New folder `src/perception/`. No new agent LLM calls (rules-only v1). Uses existing `EmotionAgent`, `Orchestrator`, and Sprint 3's `bindGlobalKeys` pattern.

## Global Constraints

- Commit prefix `feat(lyra):` or `fix(lyra):`
- Every module < 250 lines
- **All perception data stays local** — event bus in memory, aggregator rolling window in memory, no DB writes; only the derived `PerceptionBias` influences the next `DialogueTurn`

## Task 1: EventBus + Typed Events

**Files:** `src/perception/events.ts` + `.test.ts`

**Interfaces:**

```typescript
export type LyraEvent =
  | { kind: "window_focus"; at: number }
  | { kind: "window_blur"; at: number }
  | { kind: "mouse_active"; at: number }
  | { kind: "key_active"; at: number }
  | { kind: "input_submit"; at: number; charCount: number }
  | { kind: "listen_progress"; at: number; turnId: string; ms: number }
  | { kind: "skip"; at: number; turnId: string }
  | { kind: "complete"; at: number; turnId: string }
  | { kind: "proactive_dismissed"; at: number; intentId: string };

export type EventListener = (e: LyraEvent) => void;

export class EventBus {
  emit(e: LyraEvent): void;
  subscribe(listener: EventListener): () => void;
  /** Returns events within the given window (ms lookback) sorted by `at`. */
  recent(lookbackMs: number, now?: number): LyraEvent[];
}

export const bus: EventBus;  // singleton
```

Behavior:
- Bus keeps last 1000 events in a rolling buffer (memory-only)
- `recent(lookbackMs)` returns events whose `at >= now - lookbackMs`, sorted ascending
- `subscribe` returns an unsubscribe function

TDD: 5 cases (emit fires listeners, unsubscribe stops delivery, recent respects window, buffer caps at 1000, singleton export).

## Task 3: PerceptionAgent (rules-based v1)

**Files:** `src/perception/PerceptionAgent.ts` + `.test.ts`

**Interfaces:**

```typescript
import type { PAD } from "../types";
import type { BehavioralFeatures } from "./aggregator";

export type PerceptionBias = {
  pad_bias: PAD;         // additive bias, all values in [-1, 1] before combining
  confidence: number;    // 0..1 — how strongly to weight against user utterance
  reason: string;        // human-readable trigger explanation
};

export class PerceptionAgent {
  infer(features: BehavioralFeatures): PerceptionBias;
}
```

Rules (v1, deterministic — no LLM):
1. **High skip ratio (skipRatio ≥ 0.6, N ≥ 3)** → `pad_bias.p = -0.2`, `pad_bias.a = +0.1`, confidence 0.5, reason "high skip ratio suggests frustration"
2. **Long idle (isBlurred + activeMs/windowMs < 0.05)** → `pad_bias.a = -0.3`, confidence 0.4, reason "extended blur/idle suggests calm or away"
3. **Rapid submits (avgSubmitGapMs < 15000 AND submits ≥ 3)** → `pad_bias.a = +0.2`, `pad_bias.d = +0.1`, confidence 0.5, reason "rapid succession suggests engaged agency"
4. **Multiple proactive dismisses (proactiveDismisses ≥ 2)** → `pad_bias.p = -0.15`, confidence 0.6, reason "user dismissing suggests unwelcome or busy"
5. **High completion rate (completions ≥ 3, skips = 0)** → `pad_bias.p = +0.15`, confidence 0.5, reason "sustained listens suggest resonance"

Multiple rules can fire — combine via confidence-weighted average of the pad_bias, sum confidences (capped at 1.0), concatenate reasons.

TDD: 7 cases (one per rule + no rule fires + multiple rules combine).

Commit `feat(lyra): PerceptionAgent rule-based inference (Sprint 4 T3)`.

## Task 4: Wire into Orchestrator + App

**Files:**
- `src/turn/Orchestrator.ts` — accept optional `perceptionBias?: PerceptionBias` in `OrchestratorDeps`. If present, in `onUserInput` after `emotion = await emotionAgent.analyze(...)`, blend via:
  ```typescript
  const blended: CurrentEmotion = perceptionBias
    ? {
        ...emotion,
        pad: {
          p: clamp(emotion.pad.p + perceptionBias.pad_bias.p * perceptionBias.confidence, -1, 1),
          a: clamp(emotion.pad.a + perceptionBias.pad_bias.a * perceptionBias.confidence, -1, 1),
          d: clamp(emotion.pad.d + perceptionBias.pad_bias.d * perceptionBias.confidence, -1, 1),
        },
      }
    : emotion;
  ```
- `src/perception/install.ts` + `.test.ts` — attaches `window.addEventListener` for focus/blur/mousemove/keydown, throttled to 1 event per 500ms per kind; emits to `bus`. Returns an uninstall function.
- `src/settings/secrets.ts` — add `SECRET_KEYS.perceptionEnabled = "perception.enabled"`
- `src/settings/Settings.tsx` — add "Perception (privacy)" checkbox
- `src/App.tsx` — on boot, read `perceptionEnabled` (default true). If enabled, install the event listeners + construct a `PerceptionAgent`; every 60s tick `aggregate(bus)` → `agent.infer(features)` and pass the latest bias to `Orchestrator` (via a new `setPerceptionBias(bias)` method).
- `src/turn/Orchestrator.ts` — add `setPerceptionBias(bias: PerceptionBias | null): void` that stores it; `onUserInput` reads the stored bias.

Also emit events from Orchestrator: `bus.emit({ kind: "input_submit", ... })` in `onUserInput`, `bus.emit({ kind: "skip", ... })` in `onSkip`, `bus.emit({ kind: "complete", ... })` in `onSongComplete`. But guard these emissions behind a `deps.eventBus?` optional so tests don't require the bus.
