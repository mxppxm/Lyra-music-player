# v0.2 Sprint 9 · 音频特征提取

**Goal**: Extract cheap audio features (RMS energy, spectral centroid) from
each imported track, store them in the existing `library_features` table,
and let `LibraryAgent.prefilter` score candidates by PAD distance.

**Why**: The `library_features` schema has existed since Sprint 1a but has
never been written. LibraryAgent's PAD pre-filter (spec §2.6) falls back to
random / keyword-only because no feature vectors exist. Filling the table
turns the pre-filter from theoretical to real.

**Non-goal**: BPM detection — that needs onset envelope + autocorrelation
and doubles the sprint. Deferred to v0.2.1. Lyrics embedding: Sprint 10.
`bliss-rs` / ffmpeg-based extraction: rejected (ffmpeg system-dep too
heavy for personal app).

## Global constraints

- Extraction runs entirely in-process — no external tools.
- New Rust dep: `rustfft` only (~40KB, no system deps).
- Feature extraction is **best-effort**: any decode / DSP error → track's
  features row simply isn't written, LibraryAgent falls back to keyword
  match. Never throw to caller.
- `energy` and `valence` values in `[0, 1]`. Anything outside is a bug.
- Feature extraction reads at most the first 30 seconds of each track
  (keeps a 100k-track library from taking hours).

## Tasks

### T1 — Rust DSP module

- `audio_features::compute_rms(&[f32]) -> f32`  (0..1 after norm)
- `audio_features::compute_spectral_centroid(&[f32], sample_rate) -> f32`
  (normalised to 0..1 by Nyquist)
- Unit tests use programmatically-generated buffers:
  - all zeros → energy = 0
  - constant +0.5 → energy ≈ 0.5
  - white-noise-ish PRNG → energy in (0, 1)
  - pure 1kHz sine at 44.1k → centroid ≈ 1000/22050 ≈ 0.045
  - swept sine (5k) → centroid > 0.15

### T2 — File decode + tauri command

- `audio_features::extract(path) -> Result<AudioFeatures>` reads first
  30 s via symphonia, downmixes to mono, feeds DSP functions.
- Struct `AudioFeatures { energy: f32, valence: f32, duration_ms: u64 }`
- `#[tauri::command] audio_extract_features(path: String) -> Result<...>`
- Cargo test hits the existing `silence_1s.wav` fixture → energy ≈ 0.

### T3 — TS repo + wrapper

- `libraryFeaturesRepo`: `upsert({ track_id, energy, valence, duration_ms })`,
  `getByTrackId(id)`, `getBatch(ids)`.
- `extractFeatures(path) -> Promise<AudioFeatures | null>` via
  `invoke("audio_extract_features", { path })`; null on error.
- 4 tests (mock db + invoke).

### T4 — Integration into importLibrary

- After `insertTrack(row)` in `libraryScan.ts`, kick off extraction
  fire-and-forget: `void extractFeatures(row.path).then(f => f &&
  libraryFeaturesRepo.upsert(...))`.
- Failure never blocks the scan.

### T5 — LibraryAgent PAD-distance scoring

- Rewrite `prefilter(target, pad, limit)`:
  - Fetch tracks matching keyword hint OR (when no hint) random 100
  - For each candidate, fetch features (batched)
  - Score = keyword_hits × 0.4 + (1 − pad_distance) × 0.6
  - pad_distance = |pad.a − 2*energy+1| / 2 + |pad.p − 2*valence+1| / 2
    (mapping features onto arousal + pleasure axes; dominance stays keyword-only)
  - Tracks without features fall to score = keyword_hits only (backward compat)
- +3 tests: no features present → old behavior; features present → PAD
  distance changes ordering; mixed table → correct blend.
