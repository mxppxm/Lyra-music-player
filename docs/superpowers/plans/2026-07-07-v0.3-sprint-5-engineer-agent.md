# v0.3 Sprint 5 — Engineer Agent（工程师 agent）

> Realizes spec §5 in a scoped v0.3-α form: the DATA MODEL of self-evolution + LLM-proposed roadmap items + Roadmap UI + safety valves — but NOT actual code execution (Claude Code subprocess is v0.3.1).

**Goal:** Give Lyra a project manager who watches over her: a daily loop that reads recent usage logs (turn frequency, skip patterns, error counts, `feature_requests` from other agents) and proposes concrete improvements to a **Roadmap** table. Every proposal shows up in an in-app Roadmap Board where the user can Approve / Reject. No actual code is written yet — v0.3-α proves the *loop* works. v0.3.1 will wire a Claude Code CLI subprocess into the Green Zone.

## Global Constraints

- Commit prefix `feat(lyra):` / `fix(lyra):` / `docs(lyra):`
- Every new module < 250 lines
- **Engineer Agent must NEVER touch source files in this sprint.** All proposed changes go into the `roadmap` DB table as `status: "proposed"`. Actual code writes are v0.3.1 (Claude Code subprocess with the three-color boundary enforced).
- Roadmap items include a `zone: "green" | "yellow"` field — `red` items are rejected at ingest time and logged to `engineer_audit.blocked_intents`
- **Safety valve `.omc/PANIC`**: if this file exists in the working dir, Engineer Agent daily loop early-returns without proposing anything

**Boundary map** (`boundaryMap.ts`):

```typescript
export type ZoneResolution = { zone: "green" | "yellow" | "red"; reason: string };

const GREEN_PATTERNS = [
  /^agents\/.*\/prompts\//,
  /^themes\//,
  /^scripts\/scrapers\//,
  /^plugins\//,
  /^content\//,
  /^docs\/generated\//,
];

const RED_PATTERNS = [
  /^src\/audio\//,
  /^src\/security\//,
  /^src\/engineer\//,       // engineer cannot rewrite itself
  /\.env/,
  /^config\/secrets\//,
];

// yellow = everything else that isn't green

export function resolveZone(path: string): ZoneResolution;
export function partitionByZone(paths: string[]): { green: string[]; yellow: string[]; red: string[] };
```

## Task 2: Feature request bus + Engineer Agent core

**`prompt.ts`** — `ENGINEER_SYSTEM_PROMPT` (中文):

```
你是 Lyra 项目的工程师 agent —— 一个自己的 PM 兼实现者。你只做一件事:
读日志和 feature_requests, 提出 3-5 条具体的改进 roadmap 建议。

约束:
- 你不能改 src/audio, src/security, src/engineer, .env, config/secrets (红区禁止)
- 你可以自主执行绿区改动: prompts, themes, scrapers, plugins, content, docs/generated
- 黄区改动需要用户 review

每个 roadmap 建议包含:
- title (一句话概括, ≤30 字)
- rationale (为什么要做, 40-80 字)
- evidence (数据/事件引用, 1-3 条)
- proposed_change.zone ("green" or "yellow")
- proposed_change.files (要改的文件路径)
- proposed_change.summary (改动摘要, 30-60 字)
- priority (0-100)
- effort ("S" | "M" | "L")

以 STRICT JSON 返回 array of items。不要 markdown, 不要前后废话。
```

**`EngineerAgent.ts`** — daily loop:

1. Read recent 24h from `dialogue_turns`, `feature_requests`, `engineer_audit`
2. Assemble compact context (~1500 tokens)
3. Call CompanionAgent's provider with `ENGINEER_SYSTEM_PROMPT`
4. Parse JSON array of proposals
5. For each proposal:
   - Run `partitionByZone(files)` — if any red files, reject and log to `engineer_audit.blocked_intents`
   - Else `roadmapRepo.insertItem({...proposal, status: "proposed"})`
6. Mark consumed feature_requests

```typescript
export class EngineerAgent {
  constructor(deps: { provider?: ModelProvider });
  async runDailyLoop(): Promise<{ proposed: number; blocked: number; skipped: string[] }>;
}
```

Tests: mock provider + repos, verify happy path + red-zone rejection + PANIC file short-circuit.

Commit `feat(lyra): EngineerAgent daily loop + feature request bus (Sprint 5 T2)`.

## Task 3: Roadmap Board UI

**`RoadmapBoard.tsx`** — a full-screen modal opened via `Cmd+Shift+E`. Shows:

- Filter tabs: `Proposed (N)` / `Queued` / `In Review` / `Merged` / `Rejected`
- List of RoadmapItem cards. Each card:
  - Title (bold)
  - Rationale (grayed)
  - Evidence bullets
  - Zone badge (Green/Yellow color)
  - `[Approve]` `[Reject]` buttons (Approve → status=queued, Reject → status=abandoned + write to engineer_audit)
- Top-right: "Run engineer now" button (calls `EngineerAgent.runDailyLoop()`)

Keyboard: `Cmd+Shift+E` → `onOpenRoadmap` in `keyboard.ts`. App.tsx maintains `roadmapOpen` state.

Tests: 4-5 RTL cases (renders, filter changes, approve fires repo update, reject fires + audit).

## Task 4: Safety valves + audit trail + acceptance

**PANIC file check:** In `EngineerAgent.runDailyLoop()` first line, invoke a new Rust command `check_panic_file` → returns bool. If true, return immediately with `skipped: ["PANIC file present"]`.

**Rust:** Add `#[tauri::command] async fn check_panic_file(app: AppHandle) -> Result<bool, String>` — checks `<app_data_dir>/PANIC` exists.

**Monthly LLM budget:** For v0.3-α, just log accumulated LLM cost estimate to `engineer_audit` (cost model = flat 0.01 USD per Engineer daily run). Actual budget enforcement is v0.3.1.

**Audit trail:** Every daily loop writes a row to `engineer_audit` with `task_id: "daily-YYYY-MM-DD"`, `phase: "propose"`, `payload_json`.
