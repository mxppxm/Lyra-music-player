# v0.3 Sprint 7 · Perception Agent v2 (LLM-driven)

**Goal**: Upgrade rule-based `PerceptionAgent` (Sprint 4) to LLM-driven inference while
keeping the 5-rule agent as a resilient fallback. Users opt-in via Settings.

**Why**: 5 hardcoded rules cover ~30% of behavioral signal. An LLM reading the
same `BehavioralFeatures` can catch patterns the rules can't articulate — quiet
focus vs. avoidance, rapid engaged submits vs. anxious spamming, etc. Cost is
bounded (~$0.24/day at 4h use) and gated behind an opt-in toggle.

**Non-goal**: New behavioral features. New event types. Multi-turn context. All
of that is Sprint 8+.

## Global constraints

- All prompts in Chinese, matching `emotion.ts` / `companion.ts` house style.
- LLM output MUST be strict JSON — no fences, no prose surround.
- Any LLM failure (network, JSON parse, validation) MUST fall back to rule agent — never throw to caller.
- `SECRET_KEYS.perceptionMode` default = `"rule"` (opt-in for LLM).
- `PerceptionBias` shape unchanged (`pad_bias`, `confidence`, `reason`).
- `infer(features)` becomes `Promise<PerceptionBias>` — callers must `await`.

## Tasks

### T1 — Extract rule agent, make `infer` async

- Move current impl (5 rules + merge) from `PerceptionAgent.ts` → `RulePerceptionAgent.ts` unchanged.
- `PerceptionAgent.ts` becomes: exports the `PerceptionAgent` interface (`{ infer(f): Promise<PerceptionBias> }`) + a stub `createPerceptionAgent()` factory that returns `new RulePerceptionAgent()` for now.
- Move tests from `PerceptionAgent.test.ts` → `RulePerceptionAgent.test.ts`, keep signatures async (`await agent.infer(...)`).
- Update Orchestrator + App.tsx call sites to `await` the infer result.
- Cargo/vitest green.

### T2 — LLM agent + prompt

- New `prompt.ts`: `buildSystem()` + `buildUserContent(features)`. System explains role, output JSON schema, 中文 style rules. User content is a JSON blob of BehavioralFeatures (LLM-friendly, easy to parse mentally).
- New `LLMPerceptionAgent`: constructor takes `provider` + `fallback: PerceptionAgent`. `infer(features)` calls `provider.chat` (max_tokens 300, temperature 0.2, 10s timeout), parses/validates response. On ANY error → returns `fallback.infer(features)`.
- Validation: reject if pad_bias.p/a/d not in [-1,1] or confidence not in [0,1].
- Tests in `LLMPerceptionAgent.test.ts`: mock provider returning valid JSON → correct bias; invalid JSON → falls through to rule; provider throws → falls through to rule; PAD out of range → falls through.

### T3 — Route provider adds `"perception"`

- `route.ts`: add case `"perception"` — same primary/fallback as `"emotion"` (Zhipu → DeepSeek).
- One test (in existing route test file if exists, else skip — this is a two-line change).

### T4 — Settings key + factory

- `secrets.ts`: add `SECRET_KEYS.perceptionMode = "lyra.perception.mode"`. Valid values: `"rule"` | `"llm"`. Default `"rule"`.
- `PerceptionAgent.ts` factory: `createPerceptionAgent({ mode, provider }?)` — mode `"llm"` returns `new LLMPerceptionAgent(provider, ruleAgent)`, otherwise returns `new RulePerceptionAgent()`.
- `App.tsx` perception effect: read `perceptionMode` secret at boot, use factory. If mode is `"llm"`, resolve provider via `routeProvider("perception")`. Falls back to rule on secret read error.

### T5 — Settings UI toggle

- Add a radio group or select in `Settings.tsx` under a "Perception" section: "规则式（离线，免费）" / "LLM 式（Zhipu/DeepSeek，每 60 秒一次调用）".
- On change, write to keychain via `setSecret`. Persist without app restart is nice-to-have; simplest: prompt user "restart to apply" (perception loop re-inits on orchestrator change anyway; easier to just restart).

### T6 — Test pass + acceptance

- Full vitest suite green.
- Full cargo test green.
- Manual smoke: launch app in rule mode → perception ticks log rule bias. Flip to LLM in Settings → next tick should log LLM-provided reason.
