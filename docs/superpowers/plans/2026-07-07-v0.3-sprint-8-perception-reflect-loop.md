# v0.3 Sprint 8 · 感知→反思闭环（Perception self-tuning）

**Goal**: Let the Reflect Agent read recent perception outputs and
propose adjustments to the rule agent's 5 thresholds (or observe LLM
behavior). Closes the loop: Lyra's perception improves itself over
time instead of being frozen at v0 defaults.

**Why**: Sprint 4/7 shipped perception; Sprint 8 makes it learn.
Currently the 5 rule thresholds (skipRatio ≥ 0.6, active ratio < 0.05,
etc.) are hardcoded. Real usage will show which ones fire too often or
never. A once-per-reflect tuning pass is cheap and honest — no realtime
gradient descent, just a periodic self-critique.

**Non-goal**: Auto-tuning LLM prompts. LLM temperature adjustment.
Multi-agent perception (still one). Threshold ML — this is heuristic
adjustment by the Reflect prompt, not a training loop.

## Global constraints

- Threshold overrides live in SoulState (existing SQLite table).
  Never create a new persistence layer for this.
- Rule thresholds ONLY adjustable within ±50% of defaults, clamped.
  A runaway Reflect can't disable a rule entirely.
- Reflect Agent may output empty perceptionTuning — silence means
  "keep current thresholds".
- Backward compat: existing SoulState rows without perceptionTuning
  work fine (defaults used).

## Tasks

### T1 — perception_audit table + repo

- New migration: `perception_audit(id, ts, source TEXT, features_json TEXT, bias_json TEXT)`
- `perceptionAuditRepo`: `insert(row)`, `recent(n)`, `deleteOlderThan(ts)`
- Cap: 500 rows kept (delete-older-than in insert path, cheap)
- Tests: insert + recent, roundtrip via JSON

### T2 — wire App.tsx tick to write audit

- After `agent.infer(features)` in perception tick, insert audit row
  `{ ts: now, source: mode, features_json, bias_json }`
- Silently ignore write errors
- No new tests (integration verified via smoke)

### T3 — PerceptionTuning type + Rule agent honors it

- `perception/tuning.ts`: `PerceptionTuning = { skipRatio, idleRatio,
  submitGap, dismissThreshold, completionThreshold }` — all optional
  numeric overrides
- Clamp helper: overrides bounded to ±50% of default
- `RulePerceptionAgent` constructor accepts optional tuning; rules
  read thresholds from tuning ?? defaults
- SoulState schema extension (backward-compat: read undefined as {})
- +5 tests: each threshold override changes rule firing behavior

### T4 — Reflect includes perception observations

- Reflect prompt appends: "最近 20 条感知观测：…"
- Reflect output schema extends with optional `perception_tuning`
- Values echoed back as suggestions; validator clamps to ±50%
- +2 tests: valid tuning parsed / invalid tuning ignored

### T5 — Reflect apply persists tuning

- `apply.ts` writes `perceptionTuning` to SoulState
- App.tsx factory pulls tuning at boot, passes to RulePerceptionAgent
- +1 integration test: soul row roundtrip with tuning
