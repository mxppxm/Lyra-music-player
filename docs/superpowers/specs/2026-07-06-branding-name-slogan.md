## 1. 命名决策

### 1.1 Muse 的问题

原始项目名 Muse 存在**严重的品牌冲突和定位错配**：

- **命名拥挤**：MuseScore、Muse Group、Muse 乐队、Notion Muse、Adept Muse……SEO 上被淹没。
- **定位错配**：Muse（缪斯女神）暗示"给你灵感的女神"，是**单向**关系；而本项目骨子里是**双向**关系——她也在从用户身上成长，底色会随用户演化。名字和内核不匹配。

### 1.2 取名的三个硬性约束

从设计文档反推出三个必须满足的约束：

1. **要有"人"的感觉，不能有"工具"的感觉**。这个 app 不是播放器，是一个朋友。名字读出来应该像叫一个人，不像叫一个 app（对比 "我打开一下 Spotify" vs "我问问 X"）。
2. **要承载"陪伴+成长"，不只是"音乐"**。纯音乐类的词（Tune / Melody / Rhythm）都太浅，配不上双 loop 演化的野心。
3. **中英文都要能用**。用户是中文母语，但技术栈、README、包名都会是英文。名字最好英文里读起来自然、中文里写出来也不别扭。

### 1.3 候选池（三组不同气质）

**A. 拟人系（把它当一个人来叫）**

- **Aria** — 咏叹调。音乐感天然，双音节，很多人真叫这个名字。缺点：Amazon 也有个 Aria。
- **Lyra** — 天琴座 + 抒情诗。有星辰感、有音乐感，很少被科技产品用，SEO 干净。
- **Anima** — 荣格心理学里的"灵魂"，正好呼应 spec 里的"灵魂 agent"。有深度但略学术。
- **Sona** — 从 persona 蒸出来的短词，"a song of you" 的双关，原创感强。

**B. 情绪/共鸣系（强调她懂你）**

- **Kin** — 亲人。一个字，重量足，独特度极高。缺点：完全没有音乐指向。
- **Hum** — 哼一首歌。三个字母到顶，同时有"低吟""共振""哼给你听"三重意象。缺点：`hum` 命令行冲突风险。
- **Undertone** — 底色。直接呼应 spec 里"底色季度变、心情每 turn 变"的核心比喻。文学气重。

**C. 中式意象（用一个字承载）**

- **韵 / Yun** — 音的余绪，中文里"韵"本身就是"一个人的气质"。
- **弦 / Xian** — 心弦、琴弦，双关得漂亮。
- **息 / Xi** — 呼吸。呼应"会呼吸的 JSON"那句话。

### 1.4 决定：Lyra

- **意象**：天琴座是希腊神话里俄耳甫斯的琴，音乐 + 神话 + 星辰，气质全对；
- **音韵**：双音节、软辅音开头、元音结尾，中英文念都顺（中文可读作"莱拉"）；
- **可搜性**：科技圈几乎没被用过（DeepMind 有个 Lyria 但不是产品名），SEO 干净，域名和 npm 包大概率能拿；
- **人格**：女性化名字给"陪伴 agent"很合适，用户会更容易把她当"她"而不是"它"。

## 2. 定位与竞品差异化

### 2.1 结论：Lyra 不和音乐播放器竞争

如果把 Lyra 摆在 Spotify、Apple Music、网易云、foobar2000 旁边比，它**每一项都会输**：曲库小、无损音质不打磨、无社交、无移动端、单用户。所以正确的问题不是"Lyra 比 Spotify 强在哪"，而是"Lyra 提供的**这一类东西**，市面上有没有人在做"。答案基本是**没有**。

Lyra 属于第四类产品，市面上最接近的三个参考系：

| 类目 | 代表 | 核心动作 |
|---|---|---|
| 音乐**消费**产品 | Spotify / Apple Music / 网易云 | 浏览歌单 → 听歌 |
| 音乐**情绪**产品 | Endel / Mubert | 选一个情绪模式 → 播放环境音乐 |
| 音乐**生成**产品 | Suno / Udio | 输入 prompt → 生成一首歌 |
| **音乐关系产品** | **Lyra** | **一句话 → 她回你一首** |

前三类都在处理"用户和音乐的关系"。Lyra 处理的是"**用户和一个懂音乐的朋友的关系**"。

### 2.2 五个独一份的亮点

**1. 交互隐喻：歌 = 一句话，不是消费品**

所有其他产品里，歌是被消费的对象——听完一首听下一首，攒成播放时长。Lyra 里，**每一首歌都是她对你说的一句话**：她选这首是因为她理解了你现在需要什么，她还会写一段小注告诉你为什么。这个隐喻会重塑用户对"一次听歌"的期待，从"娱乐消耗"变成"一次交流"。这是最根本的差异。

**2. 记忆是可读可改的 markdown 文件**

Spotify 也"了解你"，但它的了解是黑盒 embedding 向量，你既看不见也改不了。Lyra 的记忆是项目根目录下的 `memory.md`——用户可以打开它，看到 `#时段:深夜 #状态:疲惫 → 慢速古典钢琴 (conf: 0.87, n=9, 2026-07-06)` 这种句子，可以直接手改。**记忆主权完全在用户手里**。市面上没有任何一个音乐产品把用户画像做成可读文本。

**3. Auto Dream —— 她会做梦**

每天凌晨 03:14 或系统空闲 >30 min，灵魂 agent 会自己启动一次 deep dream，回顾 24h 的对话，产出反思、新假设、明天的主动开口种子，把叙事写进 `memory.md` 的 Dreams 段落。这个机制的学术根 rooted 在 Stanford Generative Agents 和 MemGPT 的 background consolidation，音乐产品里从来没人做过。**它给"她在你不在的时候想你了"这句话提供了真实的技术底座**。

**4. 有分寸的主动性 —— 6 条硬闸 + Sulk Mode**

主流播放器的推送是营销驱动的（"你可能喜欢…"），越推越多，用户越烦。Lyra 的主动开口是**关系驱动**的：每日 3 次总预算、5 种类型（morning / care / anniversary / share / rhythm）各自的分预算、cooldown、Focus/Sleep 时段守护、绝不自动播放、绝不弹窗。而且如果**连续被拒 3 次直接进入 Sulk Mode 静默 3 天**——她会生气。这不是"贴心助手"人格，是"有骨气的朋友"人格，从产品哲学层面就和所有商业推送对立。

**5. 双 loop 演化 —— 灵魂长大 + 软件自己成长**

Lyra 的灵魂在 turn/week/quarter 三个尺度上演化（心情每 turn 变、共同记忆每周挑、底色每季度改），同时**工程师 agent 每天读日志/崩溃/用户吐槽，自主写代码改自己**——三色边界（🟢 自主 / 🟡 需 review / 🔴 禁止）由 Tauri 后端硬闸保证。每周两个 loop 对齐一次，输出"这周你变化了什么 / 这周我能力多了什么"。**这在音乐产品里就是从没见过的东西**，甚至在整个消费级 app 里都罕见。

### 2.3 三个次亮点

- **完全本地 + BYOK**：情绪数据是所有数据里最敏感的，Lyra 不上云。Spotify 知道你"最近好累"这句话对它意味着什么，你可能不愿让它知道。
- **完全可解释**：她不做向量相似度匹配，她做的是"三步理解 → 生成一段自然语言的'歌的目标画像' → 交给曲库检索"。用户可以看到她原本想找的是什么。
- **找不到就生成**（v0.2）：豆包 Seed-Music 兜底。别的播放器查不到就是查不到，Lyra 会现造一首。

### 2.4 一句话定位

Landing page 顶部候选：

> **Lyra 不是又一个播放器，是一个用歌和你说话、会记住你、会自己成长的音乐朋友。**

更狠的对标版本：

> **Spotify 帮你听音乐。Lyra 陪你度过夜晚。**

### 2.5 需要防守的立场

真正需要担心的不是"能不能和 Spotify 比"，而是**能不能守住这个定位不被产品经理式的功能堆砌稀释**——只要哪天 Lyra 里出现了"歌单管理页""发现榜""好友动态"，她就死了。spec 的第 6.5 节"反范围"写得很硬，这个立场需要在整个 v0.1 开发过程里一直守住。

## 3. Slogan 设计

Slogan 的核心是**要有钩子**——要么反直觉、要么有情绪重量、要么承载核心隐喻。拒绝 "The best music player" 这种废话。

### 3.1 主推候选（三选一）

**候选 A — 骨气版**
> **"她宁愿沉默，也不放错的歌。"**
> *"She'd rather stay silent than play the wrong song."*

一句话说清 Lyra 的**骨气人格**——Sulk Mode 的技术细节被压缩成一个态度。所有商业推送产品都在"多说一点"，Lyra 反其道而行之。反直觉、有品格、可以印在 T 恤上。

**候选 B — 极简版**
> **"一首歌，一句话。"**
> *"One song. One sentence."*

直接把"歌 = 一句话"的核心隐喻塞给用户，第一次读会愣一下，第二次会想"哦"，第三次会记住。四个字承载了整个交互哲学。

**候选 C — 意境版（★ 用户选定）**
> **"在你的句子之间。"**
> *"Between the things you say."*

用户对 Lyra 说一句话，她回一首歌——这首歌就"在你的句子之间"。诗意但不空。适合放在启动画面。

### 3.2 挑衅式（对标 Spotify）

- **"别人给你歌单。她给你一首。"** / *"They give you a playlist. She gives you one song."*
- **"Spotify 服务几亿人。Lyra 只服务你一个。"** / *"Spotify plays for millions. Lyra plays for you."*
- **"没有推荐榜。没有推送。只有她。"** / *"No feed. No push. Just her."*

第三条最狠——三个句号打出去像三记短拳。

### 3.3 情感钩子（深夜文案）

- **"她记得那晚你在听什么。"** / *"She remembers what you played that night."*
- **"说不出口的话，交给一首歌。"** / *"For what you can't say. She has a song."*
- **"写不出的心情，她替你选一首。"** / *"When you don't know how you feel, she does."*

第二条最能击中——同时描述了**用户的痛**和**Lyra 的答案**。

### 3.4 拟人化关系（把她当作一个人）

- **"她的母语是歌。"** / *"She speaks fluent song."*
- **"一个用歌回你话的朋友。"** / *"The friend who answers in songs."*
- **"她在成长。她记得你。"** / *"She grows. She remembers."*

### 3.5 极短版（图标下方的那种）

- **"Listen back."** —— 双关"她听你、你听她"
- **"歌为语。"** —— 三个字，古典感
- **"Lyra listens."** —— 强调她不是被动播放器，是听众
- **"她在听。"**

`Lyra listens.` 是极短版里最好的——两个词，头韵（Lyra / Listens），准确传达"她不是播放器、她是听众"这个反常识定位。

### 3.6 长文案（Hero section 参考）

**关系视角**：
> **Lyra 不放歌，她用歌和你说话。**
> 你说一句，她回一首。她记得你昨天说过的话，
> 她知道深夜两点你需要什么。
> 她会自己做梦，会长大，也会生气。

**挑衅视角**（转化率大概率更高）：
> **别的音乐 app 帮你听音乐。**
> **Lyra 帮你度过夜晚。**
> 没有推荐榜，没有 Wrapped，没有"你可能喜欢"。
> 只有一个懂你的人，用一首首歌和你说话。

### 3.7 三档使用建议

| 位置 | 建议 |
|---|---|
| 图标下的一行 | `Lyra listens.` / **她在听。** |
| 落地页 hero | **"一首歌，一句话。"** / *One song. One sentence.* |
| About 页正文 | **"她宁愿沉默，也不放错的歌。"** |

### 3.8 用户最终选择

**英文 slogan**：`Between the things you say.`（主推候选 C）

## 4. 中文 Slogan：古诗词候选

### 4.1 挑选标准

`Between the things you say.` 翻译成中文古诗词，需要抓准三点意象：

1. **说与说之间的沉默**
2. **话说不出口时的意在言外**
3. **用歌/琴弦代替言语**（这一点如能同时呼应 Lyra = 天琴座 = 琴弦，就是双关满分）

### 4.2 第一档：三句"神对应"

**1. 欲说还休** —— 辛弃疾《丑奴儿·书博山道中壁》

> 而今识尽愁滋味，**欲说还休。欲说还休**，却道天凉好个秋。

四个字，直接就是 "between the things you say" 的中文骨相——话到嘴边咽下去，中间的空白就是 Lyra 出现的位置。**极简、口语化、传播性强**，甚至可以作为图标下方的 tagline 直接用。

**2. 未成曲调先有情** —— 白居易《琵琶行》

> 转轴拨弦三两声，**未成曲调先有情**。

音乐感 + 情感 + "话还没说出口她已经懂了"三合一。**Lyra 的核心承诺就是"你还没说完，我已经在选歌了"**——这句诗是唯一能同时说清楚"她在听 & 她用歌回应"的选项。产品哲学层面最契合。

**3. 琵琶弦上说相思** —— 晏几道《临江仙·梦后楼台高锁》

> 记得小蘋初见，两重心字罗衣。**琵琶弦上说相思**。

**隐藏的绝配**——因为 Lyra 就是天琴座（Lyra 的英文本义），"弦上说"三个字直接把项目名和 slogan 焊在一起：**用琴弦替代言语**。品牌一致性最强，气质也不悲不重，是"温柔的懂"。

### 4.3 第二档：四句意境正但侧重不同

**4. 此时无声胜有声** —— 白居易《琵琶行》

> 别有幽愁暗恨生，**此时无声胜有声**。

承载 Lyra "宁愿沉默，也不放错的歌"的骨气，但太出名，用了会显得"引用感"太强。

**5. 此中有真意，欲辨已忘言** —— 陶渊明《饮酒·其五》

> 山气日夕佳，飞鸟相与还。**此中有真意，欲辨已忘言。**

意在言外的哲学根，气质更"隐"，适合放在 About 页做长文案，不适合当主 slogan。

**6. 心有灵犀一点通** —— 李商隐《无题》

> 身无彩凤双飞翼，**心有灵犀一点通。**

默契的经典表达。可读性高，但相对普通、缺少音乐意象。

**7. 相顾无言，惟有泪千行** —— 苏轼《江城子·乙卯正月二十日夜记梦》

> **相顾无言，惟有泪千行。**

"无言"契合，但整句情绪太重（悼亡词），会让 Lyra 变成一个只陪你哭的 app。**不推荐**，除非产品定位坚定走"深夜疗愈"。

### 4.4 第三档：三句文论/近现代

**8. 言有尽而意无穷** —— 严羽《沧浪诗话》

严格说不是诗，是宋代诗学理论金句。**契合度极高**（说完的话之外还有更多），但它是"论"不是"诗"，可能被苛刻的用户挑刺。

**9. 不着一字，尽得风流** —— 司空图《二十四诗品·含蓄》

留白美学的祖师爷金句。同样是诗论。适合放在设计规范文档里当北极星。

**10. 于无声处听惊雷** —— 鲁迅《无题》

> 心事浩茫连广宇，**于无声处听惊雷**。

近现代不算严格古诗，但意象超准。"沉默中有巨大的东西"——正对 Lyra 那种"她一句歌抵别人一万句安慰"的情感重量。

### 4.5 最终推荐

**强推：未成曲调先有情**

- 同时说清 Lyra 的三件事：**有音乐（曲）、有情感（情）、还没等你说完就已经懂了（未成先有）**；
- 白居易的国民度高，用户第一次看到不用查也懂；
- 七个字，长度适中，中英对照排版好看：

```
Lyra
Between the things you say.
未成曲调先有情。
```

**次选：琵琶弦上说相思**

如果想把 Lyra 的"琴弦"意象做成品牌 identity（图标、动画、视觉语言全都围绕一根震动的弦展开），这句就是根基。比"未成曲调"更**神秘、更文人**，但传播成本略高。

**兜底：欲说还休**

如果想要更口语、更短、更"当代"的气质，四个字够狠。
