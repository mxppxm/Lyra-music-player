**Date:** 2026-07-08
**Sprint:** 10 (v0.2.2)
**Precedes plan:** `docs/superpowers/plans/2026-07-08-v0.2-sprint-10-lyrics-embedding.md`

## 1. Motivation

`design-answers.md` §问题 1 明确写下：

> "歌词语义 embedding：把歌词丢 embedding 模型，向量库存本地。支持'来一首像《后来》那种遗憾感的歌'这种查询。"

Sprint 9 落地了 audio DSP 特征提取（energy / valence），让 LibraryAgent 的 PAD 距离预筛真的能算。但**语义 embedding** 这一环还没做——中文歌词里"遗憾感""被接住""夜里的安静"这些概念级词，靠 title/artist 关键词永远打不到。Sprint 10 补上这一层。

## 2. Goal

让 `LibraryAgent.prefilter` 在原有 `keyword × 0.4 + (1 − pad_distance) × 0.6` 的基础上，融入语义相似度分量，形成 `sem 0.5 / pad 0.3 / kw 0.2` 三分加权。

- 歌词从**本地 ID3 USLT 标签**抽取（`lofty` 已支持）
- Embedding 走**云 provider**（Zhipu embedding-3 / OpenAI text-embedding-3-small，BYOK）
- 存独立表 `library_lyrics_embeddings`，f32 BLOB + 暴力 cosine 扫描
- Import 时 fire-and-forget（跟 Sprint 9 pipeline 对称）+ Settings "Refill missing" 兜底按钮
- CompanionAgent brief **不变**（Sprint 11 再考虑歌词进 LLM 上下文）

## 3. Non-goals

- 网络歌词抓取（design-answers "网易云爬虫（灰色）需要用户拍板"，Sprint 10 不动）
- 本地 onnxruntime + bge-small 等本地 embedding runtime（跨平台 native dep 是长期负担；Sprint 9 才刚引入 rustfft）
- 歌词内容进入 CompanionAgent prompt（Sprint 11 的活）
- 全库语义搜索 UI（"来一首像《后来》"的路径是用户对 Lyra 说话 → pseudoTarget → prefilter，不是显式搜索框）
- sqlite-vec 扩展（个人库最大 100k 级，暴力扫描 < 200ms，不需要）

## 4. Design Decisions (six forks locked in during brainstorming)

| # | 分叉 | 选择 | 理由 |
|---|------|------|------|
| 1 | 歌词来源 | 只吃本地 ID3 USLT | 0 网络、0 隐私风险；缺失即降级（跟 Sprint 9 姿态一致）；网易云爬虫仍需用户拍板 |
| 2 | Embedding provider | 云 API (Zhipu / OpenAI) BYOK | Lyra 已经 BYOK；避免引入 onnxruntime 长期跨平台维护成本 |
| 3 | 向量存储 | 独立表 + BLOB + 暴力 cosine | 个人库不需要 sqlite-vec；独立表让"歌词缺失/audio 特征缺失"两条降级路径独立清晰 |
| 4 | 触发时机 | Import fire-and-forget + Settings "Refill missing" 按钮，concurrency 3 | 主路径复用 Sprint 9 pipeline；兜底按钮解决"改 key 后老歌没 embedding" |
| 5 | 打分公式 | 加权求和 `sem 0.5 / pad 0.3 / kw 0.2`，缺分量自动归一化 | 线性 blend 跟 Sprint 9 一致；降级到 kw+pad 时自动等价老公式（0.2/0.3 → 0.4/0.6） |
| 6 | CompanionAgent 集成 | 不改 brief，只改 ranking | Sprint 10 已动 4 个新模块；歌词进 LLM 是 Sprint 11 独立议题 |

## 5. Data Flow

### 5.1 Import 路径（fire-and-forget）

```
libraryScan.ts insertTrack(row)
  └→ void computeLyricsEmbedding(row.id, row.path)
       ├→ Rust: lyrics_extract(path) → Option<String>       (USLT 或 null)
       │       (any decode error → Ok(None), never throws)
       ├→ embedding provider.embed(text) → Float32Array | null
       │       (network / auth error → null, silently skipped)
       └→ lyricsEmbeddingsRepo.upsert({
              track_id, lyrics_hash, model_id, dim, embedding_blob, updated_at
          })
       (any step returns null → row simply not written; scan never blocks)
```

### 5.2 Turn 路径（LibraryAgent.prefilter）

```
prefilter(pseudoTarget: string, currentPAD: PAD, limit)
  ├→ (parallel) embedding provider.embed(pseudoTarget) → target_vec  (~250ms)
  ├→ (parallel) libraryFeaturesRepo.getBatch(all ids)
  ├→ (parallel) lyricsEmbeddingsRepo.getBatch(all ids)
  └→ for each track:
       kw   = normaliseKeyword(hits, maxHits)                  (Sprint 9)
       pad  = features ? 1 - padDistance(pad, features) : ⊥
       sem  = lyricEmb ? 1 - cosineDistance(target_vec, lyricEmb) : ⊥
       final = combineWeighted({kw, pad, sem})                 (§7)
     sort desc, take top-limit
```

### 5.3 Refill 路径（Settings 面板手动触发）

```
"Refill missing lyrics embeddings" button
  ├→ ids = lyricsEmbeddingsRepo.listMissing()
  │       (含 model_id 不匹配当前 provider 的 rows —— 切 provider 时自动 refill)
  └→ for-each with in-house semaphore (concurrency = 3):
       computeLyricsEmbedding(id, track.path)
     (silent failure; not blocking; button returns immediately, work continues in background)
```

### 7.3 Scoring (`src/agents/LibraryAgent.ts`)

```ts
const WEIGHTS = { kw: 0.2, pad: 0.3, sem: 0.5 } as const;

function combineWeighted(
  scores: Partial<Record<'kw'|'pad'|'sem', number>>
): number {
  const entries = (Object.entries(scores) as [keyof typeof WEIGHTS, number][])
    .filter(([, v]) => v !== undefined);
  if (entries.length === 0) return 0;
  const total = entries.reduce((s, [k]) => s + WEIGHTS[k], 0);
  return entries.reduce((s, [k, v]) => s + v * WEIGHTS[k], 0) / total;
}
```

**Degradation table:**

| Available | Effective weights (after normalization) | Note |
|-----------|-----------------------------------------|------|
| kw only | 1.0 | Sprint 9 "no-features" branch equivalent |
| kw + pad | 0.4 / 0.6 | **Byte-identical to Sprint 9's `PAD_WEIGHT = 0.6` formula** ✓ |
| kw + sem | 0.286 / 0.714 | New Sprint 10 path when no features |
| pad + sem | 0.375 / 0.625 | Rare (no metadata match) |
| kw + pad + sem | 0.2 / 0.3 / 0.5 | Full Sprint 10 |

## 8. Error handling policy

- **Rust `extract_uslt`**: any decode / IO error → `Ok(None)`. Never `Err(_)` back to TS. Missing tag → `Ok(None)`.
- **Embedding provider**: any HTTP / auth / rate-limit error → `null`. Log to console only.
- **Repo upsert**: any SQL error → log + swallow. Row simply not written.
- **prefilter cosine**: if dims mismatch (should not happen post-migration) → treat `sem` as unavailable.
- **User has no embedding key configured**: `createEmbeddingProvider()` returns `null`; `computeLyricsEmbedding` short-circuits; LibraryAgent silently degrades to kw+pad (identical to Sprint 9 behavior).

Everywhere: **feature missing → fall back, never throw**. This is the same posture as Sprint 9's `library_features`.
